# Freedom station save, format 17

The C++ save owner writes an explicit `mode: "freedom"` document for native New
Game. `native_continue` selects the saved mode and source path. Existing
format-16 career saves retain their objective, onboarding and Skip semantics;
the career writer and decoder are unchanged. A Freedom document never contains
an offered objective or a fabricated completion.

The format-17 recipe records a universe seed, fixed origin/home/active ordinals,
the current generator-version vector, and the station and home-planet identities.
The full `SaveRecipe`, including station orbit, is regenerated by the C++ owner
and checked against those identities. Integer identities, ordinals and ticks are
canonical unsigned decimal strings to avoid JSON number precision loss. The
generator-version vector follows `SaveGeneratorVersions` declaration order and
must have exactly 15 entries. Changing its order or meaning requires a new save
format version.

The state is docked at the origin station and records its station ID, a starter
craft ID from the independent `SeedDomain::starter_craft` stream, a simulation
tick, discoveries and world deltas. The state can roundtrip later history, but
this slice does not create in-flight Freedom state. Fuel, jump charges, saved
thrust flight, landing and walking belong to their respective follow-ups.

Decode checks the full field set, generator compatibility, seed-derived
identities, clock bounds and history bounds. It refuses unsupported or damaged
documents without rewriting the source. Save writes reuse the existing atomic
temporary-file, sync and replace path.

The seed-42 Godot study snapshot is still a fixture. Connecting the selected
Freedom save and its clock to the Godot bridge is tracked by #291; this format
does not present a fresh snapshot as a resumed save.
